## Контрольні запитання

1. Де передається ім'я сервера під час HTTPS-з'єднання?
Ім'я домену передається у повідомленні ClientHello за допомогою розширення SNI (Server Name Indication). Це дозволяє серверу зрозуміти, для якого домену потрібно встановити захищене з'єднання.
2. Чому SNI відсутнє в HTTP?
HTTP не використовує TLS, тому механізм SNI в ньому не застосовується. Ім'я сервера передається через звичайний заголовок Host.
3. Для чого використовується ALPN?
ALPN дозволяє клієнту та серверу узгодити прикладний протокол, який використовуватиметься після встановлення захищеного з'єднання. Наприклад, HTTP/2 або HTTP/1.1.

## Контрольні запитання

1. Як визначити початок шифрування в TLS 1.3?
У TLS 1.3 зашифровані повідомлення рукостискання передаються всередині записів типу Application Data. Це означає, що пасивний аналіз мережі вже не дозволяє прочитати їхній внутрішній вміст.
2. Чому ClientHello у TLS 1.3 може бути більшим?
У ньому міститься більше параметрів та розширень, необхідних для узгодження криптографічних налаштувань. Одним із таких елементів є key_share.
3. Що таке SNI?
SNI — це розширення TLS, яке дозволяє клієнту повідомити серверу потрібне доменне ім'я ще на початковому етапі встановлення з'єднання.
4. Для чого використовується ChangeCipherSpec?
У TLS 1.3 це повідомлення переважно зберігається для сумісності зі старими системами та мережевим обладнанням.

## Контрольні запитання

1. Як відбувається підтвердження володіння доменом?
ACME-центр перевіряє можливість розміщення спеціального контрольного файлу на сервері. Якщо файл доступний за визначеною адресою та містить правильне значення, домен вважається підтвердженим.
2. Чому може виникати помилка перевірки сертифіката?
Однією з причин є відсутність проміжного сертифіката. У такому випадку клієнт не може побудувати повний ланцюжок довіри до кореневого центру сертифікації.
3. Що означає SAN?
SAN (Subject Alternative Name) — це поле сертифіката, у якому вказуються доменні імена або інші ідентифікатори, для яких він є дійсним.
4. Для чого потрібен проміжний сертифікат?
Він забезпечує зв'язок між сертифікатом сервера та кореневим центром сертифікації, дозволяючи клієнту перевірити довіру до сервера.

### 4.3. Контрольні запитання

1. Чим відрізняється відсутність проміжного сертифіката від невідомого CA?
У першому випадку клієнту не вистачає одного з елементів ланцюжка сертифікатів. У другому випадку центр, який підписав сертифікат, не входить до переліку довірених.
2. Чому OpenSSL та curl можуть показувати різні результати?
OpenSSL без додаткових параметрів може перевіряти ланцюжок довіри без повноцінної перевірки відповідності доменного імені. Curl додатково перевіряє, чи відповідає домен значенням у SAN.
3. Для чого використовується параметр -k?
Параметр -k вимикає перевірку сертифіката в curl. Це може бути корисним для діагностики, але його не рекомендується застосовувати під час звичайної роботи, оскільки він знижує рівень безпеки.

## Контрольні запитання

1. Чому виміряний час може відрізнятися від теоретичного?
На тривалість з'єднання впливають навантаження системи, швидкість обробки пакетів, мережеві затримки та криптографічні операції.
2. Чому time_namelookup не завжди дорівнює нулю?
DNS-запит потребує часу на виконання та отримання відповіді. Навіть за наявності кешу можуть виникати невеликі затримки.
3. Чому повторне використання з'єднання швидше?
Під час повторного запиту не потрібно заново створювати TCP-з'єднання та проходити повний процес TLS-рукостискання. Завдяки цьому зменшуються мережеві витрати.
